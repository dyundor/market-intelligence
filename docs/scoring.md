# Buyer Qualification Scoring

Last updated: 2026-08-08 (Sprint 12 — Data Quality Improvement)

## Overview

The qualification engine scores every buyer 0–100 and assigns a priority tier (A/B/C). Scoring is **explainable**: every contribution is traceable to a specific factor with a weight and value.

All scoring runs server-side in `lib/qualification/`. The frontend consumes results via API only.

## Scoring Factors

| # | Factor | Weight | Metric Function | Input | Description |
|---|--------|--------|----------------|-------|-------------|
| 1 | Shipment volume | 20% | `logScale(value, 100)` | `total_shipments` | Total historical BOLs. 100 BOLs = score 100. Diminishing returns beyond 100. |
| 2 | Shipment recency | 20% | tiered `recencyScore(date)` | `latest_shipment_date` | Days since last shipment: 0–30d=100, 31–90d=80, 91–180d=50, 181–365d=25, >365d=0. NULL = 0. |
| 3 | Supplier diversity | 15% | `ratioScale(value, 5)` | `supplier_count` | Number of distinct suppliers. 5+ suppliers = score 100. |
| 4 | Container volume | 15% | `logScale(value, 50)` | `selected_month_containers` | Container count in selected months. 50 containers = score 100. |
| 5 | Freight value | 10% | `logScale(value, 100000)` | `selected_month_freight_usd` | Estimated freight spend. $100K = score 100. |
| 6 | Product relevance | 10% | keyword match with exclude penalty | `products` (description) | Keyword hits against product category. Each hit = +25. Exclude keyword hits = -20 each. Clamped 10–100. |
| 7 | Identity confidence | 5% | `ratioScale(value, 100)` | `identity_confidence` | Entity identity confidence (0–100). 100 = exact match. |
| 8 | Data coverage | 5% | discrete tiers | `total_shipments`, `search_query` | 100 = has shipments. 50 = product-specific query. 30 = identity verified. 10 = unknown. |

### Score Calculation

Each factor contribution = `clamp(value * weight / 100, 0, 100)` rounded to integer.

Total score = `clamp(sum of all contributions, 0, 100)`.

### Priority Thresholds

| Score Range | Priority | Meaning |
|-------------|----------|---------|
| 55–100 | **A** | High-value buyer — prioritize for outreach |
| 25–54 | **B** | Moderate buyer — secondary priority |
| 0–24 | **C** | Low-value buyer — deprioritize |

Thresholds defined in `lib/qualification/types.ts`: `PRIORITY_THRESHOLDS = { a: 55, b: 25 }`

## Metric Functions

Defined in `lib/opportunity/metrics.ts`:

### logScale(value, benchmark)
```
if value <= 0: return 0
return clamp(100 * ln(1 + value) / ln(1 + benchmark), 0, 100)
```
Logarithmic scale gives high differentiation at low values and diminishing returns at high values. A buyer with 200 shipments scores only slightly higher than one with 100.

### ratioScale(value, benchmark)
```
return clamp(100 * min(value, benchmark) / benchmark, 0, 100)
```
Linear scale capped at benchmark. A buyer with 3 suppliers scores 60 (3/5 × 100).

### recencyScore(date)
```
if !date: return 0
days = (now - date) / 86,400,000
if days <= 30: 100    // very recent
if days <= 90: 80     // recent
if days <= 180: 50    // moderately recent
if days <= 365: 25    // old
otherwise: 0           // very old or inactive
```
Tiered decay provides better differentiation than linear decay. Updated in Sprint 11.

## Positive Factors (Reasons)

Generated by `gatherPositiveFactors()` in `lib/qualification/factors.ts`:

| Reason | Trigger |
|--------|---------|
| High shipment volume | `total_shipments >= 50` |
| Recent imports (≤180 days) | Latest shipment within 180 days |
| Multiple suppliers | `supplier_count >= 3` |
| Containerized cargo | `selected_month_containers >= 1` |
| High freight value | `selected_month_freight_usd >= 10000` |
| Strong product relevance | Relevance factor value ≥ 50 |
| High identity confidence | `identity_confidence >= 80` |

## Risk Factors (Warning Flags)

Generated by `gatherRiskFactors()` in `lib/qualification/factors.ts`:

| Reason | Trigger |
|--------|---------|
| Few shipments | `total_shipments < 5` |
| No recent activity | No latest_shipment_date or > 365 days ago |
| Single supplier | `supplier_count === 1` |
| No containers | `selected_month_containers === 0` |
| No verified website | `website_status` not `verified_company_site` or `verified_forwarder_site` |
| Low identity confidence | `0 < identity_confidence < 70` |
| No shipment data | `total_shipments` is NULL or 0 |
| Product mismatch | Product description contains excluded keywords |
| Missing supplier relationships | `total_shipments >= 50` but `supplier_count === 1` |

## Product Classification

Products are defined in `lib/products/dictionary.ts`. Each category has:

- **keywords**: Positive matches — these terms indicate the product IS in this category
- **aliases**: Alternative names that also resolve to this category
- **excludeKeywords** (Sprint 12): Negative matches — these terms indicate the product is NOT bathroom-related (e.g. "kitchen faucet", "sauna", "shower door")

When scoring product relevance, each keyword match adds +25 to the relevance score. Each exclude keyword hit deducts -20. This penalizes non-bathroom products (e.g. sauna equipment matched via "shower faucet" query).

## Data Coverage Tiers

Introduced in Sprint 12 to prevent query-only candidates from ranking near real shipment buyers.

| Tier | Value | Condition |
|------|-------|-----------|
| Shipment verified | 100 | `total_shipments > 0` |
| Product query match | 50 | Search query contains product keywords (faucet, shower, bath, tap, 龙头, 花洒) |
| Identity confirmed | 30 | `identity_confidence >= 80` but no shipment data |
| Unknown | 10 | No data at all |

## Data Flow

```
Query Engine → rankBuyers() → normalizeRanking()
  → for each ranked buyer: qualifyBuyer(buyer, context)
    → computePriorityScore(row, context)
    → priorityFromScore(score)
    → gatherPositiveFactors(row, factorMap)
    → gatherRiskFactors(row)
  → attach { priority, qualificationScore, positiveFactors, riskFactors }
  → API response → Frontend renders badges + score + factors
```

### Issues Identified

1. **Data coverage (HIGH)**: Only 14/50 (28%) importers have shipment data. 36 importers are from generic queries with NULL total_shipments.
2. **Missing major buyers (HIGH)**: Ferguson, Lowe's, HD Supply, Wolseley, Moen, Delta, Kohler, American Standard, Toto not in database.
3. **Inactive buyers**: 3 buyers (LDR Global, Posey Supply, Giagni) with last shipment >2 years ago still rank B-tier due to high historical volume.
4. **Non-plumbing companies**: Russian Sauna (234 shipments) appears in dataset from a "shower faucet" query capture.
5. **Website coverage**: Only 1/50 importers has a verified website.
6. **No duplicates detected**: Good.

### Recency Scoring Change (Sprint 11)

**Before** (linear decay): `score = 100 * (1 - days/180), clamped 0–100`
- Mjf Group (May 2026, ~83 days = 54): score 54, B-tier
- AquaPro (Jul 2026, ~24 days = 87): score 87

**After** (tiered decay): staged intervals
- Mjf Group (May 2026, ~83 days → 31–90d bucket = 80): score 80
- AquaPro (Jul 2026, ~24 days → ≤30d bucket = 100): score 100

Result: Mjf Group correctly promoted from B to A (278 shipments + recent activity).

### Known Limitations

1. **Container/freight data unavailable**: Most importers show 0 containers and $0 freight because the selected_month columns are aggregated per-query, not globally stored. This zeros out 25% of scoring weight (15+10).
2. **Product relevance is coarse**: Without keyword-matched product descriptions, relevance defaults to 70 for any importer with shipments, masking non-plumbing companies.
3. **Supplier counts may be incomplete**: Many importers show supplier_count=1 despite high shipment volumes, indicating incomplete relationship data.
4. **Identity confidence clusters at 90**: 68% of importers have identity_confidence=90, making this factor weakly discriminating.

### Future Improvements

- Run targeted product-specific ImportYeti queries to populate missing shipment data
- Run website verification enrichment to discriminate the "missing_website" risk factor
- Add selected-month-container and freight aggregation to a persistent column
- Improve product relevance with HS-code-level matching
- Consider a search_query quality score to penalize generic-query importers
